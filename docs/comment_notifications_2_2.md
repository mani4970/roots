# 댓글·답글 알림 적용

기준: `roots_safe_current_20261021_1656.zip`. SQL은 기존 순서대로 `supabase/170_qt_comment_notifications_2_2.sql`에 있습니다.

1. 패치를 프로젝트 폴더에 덮어씁니다.
2. Supabase SQL Editor에서 170번 SQL 전체를 실행합니다. 마지막 한 행의 여섯 항목은 모두 `true`여야 합니다. 169번까지 적용한 상태에서 실행하며, 다시 실행해도 기존 댓글·알림·읽음 기록을 유지합니다.
3. Vercel의 Roots 프로젝트 → Settings → Environment Variables에서 **Production**에 `CRON_SECRET`을 Secret 유형으로 설정합니다. 이미 있다면 유지합니다. 새 값이 필요하면 Mac 터미널에서 `openssl rand -hex 32`를 실행해 나온 값을 사용합니다. 비밀값은 소스나 safe ZIP에 넣지 않습니다. 이 값은 예약 작업이 서버에 접근할 때 사용합니다.
4. 로컬에서 화면을 확인하고 커밋·푸시합니다. 환경 변수 설정은 새 배포부터 반영됩니다.
5. 배포 완료 후 Vercel 프로젝트의 Cron Jobs에서 `/api/comment-notifications/dispatch`가 매분 실행되는지 확인합니다. 정상 실행 응답은 `ok: true`와 처리 건수입니다. `401`이면 Production의 `CRON_SECRET` 설정과 새 배포 반영 여부를 확인합니다.

기존 서버용 `SUPABASE_SECRET_KEY`와 iOS APNs / Android FCM 설정을 그대로 사용합니다. 추가 메신저 API, 네이티브 플러그인, 앱스토어 업데이트는 필요하지 않습니다. 웹·홈 화면 추가 방식에서는 앱 안 알림 목록을 제공하며 웹 푸시는 추가하지 않습니다.

## 사용자 동작

- 새 댓글 → 묵상 작성자. 답글 → 묵상 작성자와 원댓글 작성자. 작성자 본인은 제외하고 같은 수신자는 한 번만 기록합니다.
- 과거 댓글은 일괄 알리지 않습니다. 수정·좋아요는 알림을 만들지 않습니다.
- 동역자·그룹·전체에서 같은 묵상의 댓글 알림을 통합합니다. 네 가지 묵상 형식 모두 적용합니다.
- 공동체 상단 종 버튼에서 목록을 열고 하단 공동체 탭에도 미확인 표시를 보여줍니다. 목록을 열기만 해서는 읽음 처리하지 않습니다.
- 선택한 댓글을 표시하면 그 알림 하나만 읽음 처리합니다. 오래된 댓글도 직접 찾아가며, 답글은 펼쳐서 보여줍니다.
- 숨김·차단·공개 철회·삭제는 조회와 전송 때 현재 권한으로 확인합니다. 삭제된 댓글의 알림 기록은 함께 정리합니다.
- 알림 설정의 댓글·답글 항목은 푸시를 제어합니다. 푸시를 꺼도 앱 안 목록은 유지합니다.
- 기기 밖 푸시에는 댓글 원문을 포함하지 않습니다. 서버 전송 결과와 실제 기기 표시 여부는 다를 수 있으므로 설치 앱에서 최종 확인합니다.

## 배포 후 두 계정 확인

1. A의 묵상에 B가 댓글을 남깁니다. A에게만 알림이 오는지 확인합니다.
2. A가 B의 댓글에 답글을 남깁니다. B가 답글 알림을 받고 해당 답글로 이동하는지 확인합니다.
3. 여러 공개 범위에 공유한 같은 묵상에서 중복 알림이 생기지 않는지 확인합니다.
4. 댓글 알림 푸시를 끈 상태에서도 앱 안 목록에 새 알림이 보이는지 확인합니다.
5. 알림 목록을 여는 것과 댓글을 선택하는 것의 읽음 처리가 다른지 확인합니다. 다른 기기에서도 읽음 상태가 이어져야 합니다.
6. iPhone·Android 설치 앱의 백그라운드/종료 상태와 Mac·iPad의 앱 안 목록을 확인합니다. Android 뒤로가기는 열린 목록·안내·묵상 순서로 닫혀야 합니다.

기기 현지 날짜, 묵상 저장·임시저장, streak·progress, 기도 기록, 배지·보상 계산은 이 패치의 수정 대상이 아닙니다.
